# pptx reference suite (`testdata/pptx/provisional-NN-*.pptx`) - PROVISIONAL

Thirty-three small decks (each at most 10 slides, all < 80 KB) covering the Rusuite Show feature subset, one topic per file, combinations in 22 and 25; 26 and 27 carry slide transitions and animations, 28 flowchart shapes with glued connectors, 29 tables, 30 sections and footers, 31 picture adjustments, 32 charts, 33 hyperlinks, click actions and a video. They are generated by headless LibreOffice 25.2 and are **PROVISIONAL**: they only prove that LibreOffice can read them. Replace them with PowerPoint-authored files (same topic list) when the owner provides them; keep `manifest.json` accurate.

The older `provisional-basic.pptx` (from `scripts/gen-testdata.sh`) stays and is not in the manifest.

## Regenerating

```
scripts/gen-pptx-suite.sh            # python generator -> .fodp -> soffice -> pptx (+ gen.py post) + manifest.json
scripts/gen-pptx-suite.sh --verify   # existing files: valid zip, < 80 KB, converts to non-empty PDF, manifest checks
bash scripts/roundtrip.sh --identity testdata/pptx   # 34/34 incl. provisional-basic.pptx
RUSUITE_REWRITE=target/debug/examples/rewrite bash scripts/roundtrip.sh testdata/pptx   # our rewrite of every deck opens in LibreOffice
```

Source: `scripts/testdata-src/pptx/gen.py` (stdlib only; a `Deck` class plus one function per topic; run with `python3 -I`). Images are three generated 48x48 PNGs (gradient, checkerboard, plasma). The script rewrites all 33 files and the manifest; output is not byte-reproducible across runs (26 and 27, later 28 and 29, then 30 and 31, then 32 and 33 were added by converting only their `.fodp` files, so the older files stayed byte-identical).

LibreOffice links audio and video by absolute file URL instead of embedding them, so `gen.py post` also embeds the media of decks that have some (33): the external `video`/`media` relationships are pointed at `ppt/media/mediaN.ext`, which is added with its content type. The "video" of deck 33 is a 28-byte WebM (EBML) header – enough for the package, not playable.

LibreOffice cannot export PowerPoint 2010 sections, so `gen.py post PPTXDIR` (run by the script after the conversion) adds a `p:extLst/p:ext/p14:sectionLst` to `ppt/presentation.xml` of every deck that declares sections (30); the rest of the file stays as LibreOffice wrote it. LibreOffice drops the sections again when it re-saves a deck, so the round-trip harness (`roundtrip.sh`) only checks that LibreOffice opens our rewrite; the section round trip itself is checked by `crates/fmt-pptx/tests/suite.rs` (read → write → read).

## manifest.json

Array of `{ "file", "topic", "features": [...] }`. The slide XML checks done by `--verify` (`gen.py check`) are listed per feature below.

## Feature vocabulary

| Feature | Meaning | Check in slide XML |
|---------|---------|--------------------|
| `slides:N` | number of slides | `ppt/slides/slideN.xml` count |
| `size:16x9` `size:4x3` | slide size (28 x 15.75 cm / 25.4 x 19.05 cm) | `p:sldSz` ratio |
| `layout:title` | slide with title (and subtitle) placeholders only | title placeholder present |
| `layout:titleContent` | title + content (outline) placeholder | title and body placeholders present |
| `layout:blank` | no placeholders | a slide without `p:ph` |
| `shape:<prst>:count=N` | preset geometry used N times (`rect`, `roundRect`, `ellipse`, `line`; `rightArrow` in 20; `flowChartProcess`, `flowChartDecision`, `flowChartTerminator`, `flowChartDocument`, `flowChartInputOutput`, `flowChartConnector`, `star5`, `hexagon`, `wedgeRectCallout` in 28) | at least N `a:prstGeom prst=...` (rect also matches text boxes and placeholders) |

| `connector:attached` | connector glued to shapes (ODF `draw:start-shape`/`draw:end-shape` + glue points) | `a:stCxn` |

| `text:color` `text:size` `text:font` | run colour, size, font family | `sz=`, `a:latin` |
| `text:align:left\|center\|right` | paragraph alignment | `algn="ctr\|r"` (left is the default, LibreOffice omits it) |
| `text:anchor:top\|middle\|bottom` | vertical text anchor | `anchor="t\|ctr\|b"` |

| `background:solid` | solid slide background | `p:bg` |
| `transition:fade\|push\|wipe\|cover\|split` | slide transition (ODF `smil:type` fade/pushWipe/barWipe/slideWipe/barnDoorWipe) | `<p:fade`, `<p:push`, … |

| `section:count=N` | PowerPoint 2010 sections (added by `gen.py post`) | exactly N `<p14:section ` in `presentation.xml` |

## What LibreOffice's export does differently from PowerPoint

- Placeholders: the title is `<p:ph type="title"/>` even on a title-only or first slide (PowerPoint uses `ctrTitle`); the content (outline) placeholder is written as a bare `<p:ph/>` without `type="body"` or `idx`. Subtitle is `type="subTitle"`. Slides reference LibreOffice-generated layouts and masters, not the PowerPoint layout names ("Title Slide", "Title and Content").
- Free text boxes are `p:sp` with `txBox="1"` and `prst="rect"`; so are most shapes, hence `rect` counts include them.
- Lines are written as `p:sp` with `prst="line"`, not `p:cxnSp` as PowerPoint does.
- Default alignment (`algn="l"`) and zero rotation/flip are omitted; bullet levels are `lvl` 0-based and level 1 has no attribute.
- Default text insets differ (`lIns="117000"` etc.), and shapes carry an explicit empty `<p:style>` with zero reference indexes.
- Pictures get an empty `descr=""`; no alt text is written.
- Transitions: LibreOffice writes an effect-less `p:transition` (`spd="slow" p14:dur="2000"`) on every slide without one, and ignores `presentation:transition-speed` (durations come out as 2 s). Its export maps ODF `fromRight` to `dir="l"` (the direction of motion, as PowerPoint), but its import reads `dir="l"` back as `fromLeft`.
- Animations: no `grpId`/`p:bldLst`, `additive="repl"`, and Fly Out is written with `presetSubtype="0"` (the direction is only in the `ppt_x`/`ppt_y` formulas). "Zoom" here is LibreOffice's `ooo-entrance-fade-in-and-zoom`, exported as PowerPoint's Zoom (`presetID` 53).
- Connectors: elbows between sites at right angles are written as `bentConnector2`, other routes as `bentConnector3`–`5`/`curvedConnector2`–`5` with adjust values outside 0–100000; glue points map ODF 0 top / 1 right / 2 bottom / 3 left to OOXML `idx` 0 top / 3 right / 2 bottom / 1 left. Connectors get empty names.
- Tables: no `a:tableStyleId` and no `tableStyles.xml` part (the ODF table template and first-row/banding flags are dropped); every cell carries explicit black 0.57 pt (7200 EMU) borders, its fill (or `a:noFill`) and 1 mm margins, and every run explicit Arial 18 pt black.
- Custom shapes get `auto-grow-height` in ODF by default, which shrinks them to the text height; the generator disables it so sizes stay as specified.
- Masters and layouts: the master has no placeholders, background or text styles (Rusuite adds the Office master's placeholders on import); every master has one layout named "Default" of `type="title"` (sometimes a second one of `type="blank"`), referenced by slides whatever their placeholders – Rusuite moves such slides to an inferred standard layout.
- Footers: slide placeholders `<p:ph type="dt" idx="1"/>`, `ftr idx="2"`, `sldNum idx="3"` with an empty `p:spPr` (positions from the master), the footer as plain text, the slide number as `a:fld type="slidenum"`, a fixed date as text.
- Charts: written without an embedded workbook (no `c:externalData`), with LibreOffice's colours as explicit `c:spPr` fills, `c:f` texts like `label 0`/`categories`/`0` (not ranges) and its own `c:txPr`; data read by rows unless the ranges use the `local-table.$B$2:.$B$5` syntax.
- Links and media: text links as `a:hlinkClick` with external relationships, slide links as `hlinksldjump`, shape actions as `hlinkshowjump`; media as `p:pic` with `a:videoFile r:link` and `p14:media r:link` (not `r:embed`), both external `file://` URLs (see `post`), no poster `a:blip`, PowerPoint 2010's media extension under LibreOffice's own `p:ext uri`.
- Pictures: crop as `a:srcRect` in the image's proportions, `a:grayscl`, `a:biLevel thresh="50000"`, `a:lum bright contrast`, `a:alphaModFix amt`.

## Picture adjustments in the UI (`model_show::PictureProps`)

How the Show UI draws a picture's adjustments (the model mirrors PowerPoint; `PictureProps::css_filter` returns the CSS approximation below):

| Property | Meaning | CSS `filter` (approximation) | Exact canvas/SVG rendering |
|---|---|---|---|
| `crop {left, top, right, bottom}` | fractions of the image cut off each edge (negative: padding) | – | draw the source rectangle `sx = left·W`, `sy = top·H`, `sw = (1 − left − right)·W`, `sh = (1 − top − bottom)·H` into the shape's box (`drawImage(img, sx, sy, sw, sh, x, y, w, h)`) |
| `brightness` `b`, `contrast` `c` (−1…1) | PowerPoint's Picture Corrections (`a:lum`) | `brightness(1 + b) contrast(slope)` | per channel (0…1) `out = slope·in + 0.5 − 0.5·slope + b`, `slope = 1/(1 − c)` for `c > 0`, `1 + c` otherwise (`PictureProps::transfer`; SVG `feComponentTransfer type="linear"`) |
| `recolor: grayscale` | `a:grayscl` | `grayscale(1)` | luminance `0.299 r + 0.587 g + 0.114 b` |
| `recolor: sepia` | `a:duotone` black → `D9C3A5` | `sepia(1)` | duotone below with `dark = 000000`, `light = D9C3A5` |
| `recolor: blackWhite {threshold}` | `a:biLevel` | `grayscale(1) contrast(100)` | luminance < threshold → black, else white (`feComponentTransfer type="discrete"`) |
| `recolor: duotone {dark, light}` | `a:duotone` | `sepia(1)` | luminance `L`, colour `dark + L·(light − dark)` |
| `transparency` `t` (0…1) | `a:alphaModFix amt = 1 − t` | `opacity(1 − t)` | `globalAlpha = 1 − t` |
| `geometry` | outline of the picture (`a:prstGeom`, `None` = rectangle) | – | clip the image to the preset's path (the `shapePaths` request gives it) |
| `shadow {color, alpha, blur, distance, directionDeg}` | outer shadow (`a:outerShdw`) | `drop-shadow(dx dy blur/2 rgba)` with `dx = distance·cos(dir)`, `dy = distance·sin(dir)` in px (9525 EMU/px) | canvas `shadowColor`, `shadowBlur = blur`, `shadowOffsetX/Y` |
| shape `line` | the picture border (`a:ln`) | – | stroke the outline after the image |

Order: crop → recolour → brightness/contrast → transparency; the shadow is drawn under the (clipped) picture, the border on top.
