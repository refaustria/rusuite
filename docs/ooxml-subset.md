# OOXML Subset

Which parts and elements of Office Open XML (ECMA-376, transitional) Rusuite reads and writes, per
format, and where it is knowingly lossy. Scope rules are in the README; the crate layout is in
[architecture.md](architecture.md).

Common to all three formats (`fmt-ooxml`):

- **Package.** ZIP container, `[Content_Types].xml` (Default + Override), package and part relationships,
  OPC part-name rules. The main part is found through the `officeDocument` relationship (transitional or
  Strict URI).
- **Reading** is tolerant: elements and attributes are matched by local name (any namespace prefix);
  content outside the subset is dropped with a warning in `ReadOutput.warnings`, never silently.
- **Writing** regenerates every part from the model with the standard declaration
  (`standalone="yes"`) and deterministic output; characters XML 1.0 cannot carry are dropped (SpreadsheetML
  text keeps them as `_xHHHH_`). Relationship and content types come from `fmt_ooxml::{rel, ct}`.
- **Theme** (`*/theme/theme1.xml`, `fmt_ooxml::theme`): color scheme (`a:srgbClr`, `a:sysClr/@lastClr`)
  and major/minor fonts are read into `core_model::Theme`; format/effect styles are not modelled. Each
  writer can put the imported theme part back verbatim (conditions per format below); otherwise it emits a
  minimal Office-like theme (Word: `dk1`/`lt1` as `a:sysClr`; Show: generated from the model's theme).
- **Charts** (`*/charts/chartN.xml`, `fmt_ooxml::chart`): `c:chartSpace` ↔ `core_model::chart::Chart`
  (P8-18, used by xlsx; meant for pptx/docx charts too). The mapping is listed under xlsx below;
  caches are written from a `ChartData` source (Calc: the workbook), else from the model.
- **docProps** (`core.xml`, `app.xml`) are ignored on read and written minimal.

## xlsx (`fmt-xlsx`)

`fmt_xlsx::read(&[u8]) -> Workbook` and `fmt_xlsx::write(&Workbook) -> Vec<u8>` (plus
`read_with_warnings`, `read_with_context` / `write_with_context`, and native-only `read_path` /
`write_path`). The crate compiles for `wasm32-unknown-unknown`. Transitional SpreadsheetML only.

| `<conditionalFormatting sqref><cfRule>` | → `Workbook::add_cf_rule` per rule, ordered by `priority` across all elements (ties in document order), renumbered `1..`; `sqref` (space-separated ranges) → `ranges`; `dxfId` → the `<dxf>`; `stopIfTrue`. Formulas: `_xlfn.` stripped, relative to the top-left cell of the ranges' bounding box. Other types (`timePeriod`, …), unknown `dxfId`s, unparsable formulas and invalid `sqref`s drop the rule (warning). A `<cfRule><extLst>` (Excel 2010 data bar extension) is ignored. |
| `<dataValidations><dataValidation>` | → `Workbook::set_validation` (a later validation wins on overlapping cells). `type` `none` → `Any`, `list`, `whole`, `decimal`, `date`, `time`, `textLength` (`operator`, default `between`; `formula2` for `between`/`notBetween`), `custom`; a list `formula1` in double quotes (`"a,b,c"`, `""` = `"`) → `Literal` values split at `,`, otherwise → `Formula`. `allowBlank`, `showDropDown` (inverted: `1` hides the dropdown), `showInputMessage`, `showErrorMessage`, `errorStyle` (`stop`/`warning`/`information`), `errorTitle`, `error`, `promptTitle`, `prompt`. Absent flags read as false. Malformed validations are dropped (warning). `imeMode` ignored. |
| Worksheet `<extLst>` | `x14:dataValidations` (Excel 2010 list sources on other sheets, `<x14:formula1><xm:f>` and `<xm:sqref>`) are read like `<dataValidation>`s (warning: saved as standard data validation). `x14:conditionalFormattings` (data bar extensions, x14-only icon sets and rules) are dropped (one warning with the rule count). Other extensions are ignored silently. |

All parts are regenerated (only the theme comes from `XlsxContext` when given); output is
byte-for-byte deterministic for the same `Workbook` and context.

### Known lossy points

- Properties equal to the workbook default font, `Fill::None`, `HAlign::General`,
  `VAlign::Bottom`, `wrap_text: Some(false)`, `indent: Some(0)`, `Underline::None` and
  `bold/italic/strike: Some(false)` are written but read back as `None` (inherit).
- `FontFace::Theme` is written as the named font (`Calibri Light` / `Calibri`) and reads back as
  `FontFace::Named`. `RunProperties::highlight` and dotted/dashed/wavy underlines have no
  SpreadsheetML equivalent (underline written as single).
- A content cell without an own style inside a styled row/column is written with the row/column
  style and reads back with that style as its own style.
- Formula text of shared-formula dependents is the engine's canonical form.
- A row hidden by hand inside a range with active column filters reads back as hidden by the
  filter (`filtered`). `SortKey::kind` (`numbers`/`text`) has no SpreadsheetML attribute and reads
  back as `auto`. An `Eq` criterion written as a pattern of the contains family (`*x*`) reads back
  as `Contains`.
- Conditional formatting: rules sharing a range are written as separate `<conditionalFormatting>`
  elements (Excel groups them). Excel 2010 extensions (data bar gradients/negative bars, x14 icon
  sets) are lost; `stdDev` of above/below average rules and strict (`gte="0"`) icon thresholds
  are approximated. Theme colours of colour scales are interpolated with the default Office theme.
- Data validation: literal list values containing `,` cannot be represented (split on read);
  x14 data validations are written back as standard ones.
- Charts: all text formatting (fonts, sizes, colors of titles, labels and axes), layouts (manual
  positions of plot area, legend, titles), chart/plot area fills and borders, error bars, data
  tables, per-point labels, up/down bars, high-low/drop lines, explosions, secondary category axes,
  date axis units and multi-level categories are lost; gradients and patterns become solid fills.
  Gap width/overlap are kept once per chart (Excel stores them per bar group); settings that do not
  apply to the chart kind (gap width of a line chart, axes of a pie) are not written. Rich-text
  titles lose their runs. `mc:AlternateContent` styles are written as plain `c:style`. Drawing
  pictures and shapes are dropped. A chart reference to a deleted sheet keeps its text (not
  `#REF!`).

## docx (`fmt-docx`)

`fmt_docx::read(&[u8]) -> Document` and `fmt_docx::write(&Document) -> Vec<u8>` (plus
`read_with_warnings`, `read_with_context` / `write_with_context`, and native-only `read_path` /
`write_path`), mapping to `model_text::Document` (ADR 0006). The crate compiles for
`wasm32-unknown-unknown`. Transitional WordprocessingML; parts are found by relationship type
(last path segment, so strict relationship types resolve too). Unsupported content never fails
a read: it is dropped with a warning (repeats are merged into one line with a count).

### Read

| Part / element | Handling |
|---|---|

### Known lossy points

- Highlight colors other than Word's 16 are written as the nearest named color (squared RGB
  distance): `black 000000, blue 0000FF, cyan 00FFFF, green 00FF00, magenta FF00FF, red FF0000,
  yellow FFFF00, white FFFFFF, darkBlue 000080, darkCyan 008080, darkGreen 008000, darkMagenta
  800080, darkRed 800000, darkYellow 808000, darkGray 808080, lightGray C0C0C0`. Run shading
  (`w:shd`) is never written.
- Complex-script twins (`bCs`, `iCs`, `szCs`) are written equal to `b`/`i`/`sz`; east-asian and
  complex-script fonts (`eastAsia`, `cs`) are not kept.
- `firstLine` and `hanging` are mutually exclusive: if both are set, only `hanging` is written.
- Line spacing `Multiple(m)` is stored in 240ths of a line (`round(m × 240)`).
- Run formatting of a break or image is not modelled (written without `w:rPr`).
- Paragraph direction (`w:bidi`, `w:rtl`) is not modelled; RTL paragraphs keep their visual
  alignment but lose their direction.
- Legacy horizontal merges (`hMerge`) stay separate cells. A table style's text formatting
  (`pPr`/`rPr`, also conditional) is kept but not layered into `resolve_paragraph_props`/
  `resolve_run_props` (see `Document::table_text_props`); row-level (`trPr`) style formatting is
  dropped.
- Floating images: `relativeHeight` (z-order), `locked`, `layoutInCell`, the wrap polygon and margin
  references other than margin/page/column/character and margin/page/paragraph/line are not kept;
  `wrapThrough` becomes `wrapTight`.
- A standalone list (`abstract_id: None`, e.g. created by `ApplyList`) is written on an abstract
  definition of its own and reads back as a list using it (same levels and labels).
- Fields other than `PAGE`, `NUMPAGES`, `DATE`, `TIME`, `FILENAME`, `AUTHOR` (and `TOC`) become
  plain text; modelled fields are written as `w:fldSimple` (complex fields are not kept as such).
- A table of contents keeps only its levels, title and entries (rebuilt from the headings on read);
  other `TOC` switches, the entries' own formatting and stale cached entries are not kept.
- Header/footer parts shared by several sections are read into each section and written once per
  section. Document-level `w:evenAndOddHeaders` is only written for a document without a settings
  part from the file (the file's settings are kept verbatim).
- Section foot/endnote properties (numbering format, position) are not modelled.

## pptx (`fmt-pptx`)

`fmt_pptx::read(&[u8]) -> Presentation` and `fmt_pptx::write(&Presentation) -> Vec<u8>` (plus
`read_with_warnings`, `read_with_context` / `write_with_context` with `PptxContext`, and
native-only `read_path` / `write_path`), mapping to `model_show::Presentation` (ADR 0008). The
crate compiles for `wasm32-unknown-unknown`. Transitional PresentationML + DrawingML; parts are
found by relationship type (last path segment). Unsupported content never fails a read: it is
dropped with a warning (repeats merged into one line with a count). The XML DOM/writer and the
theme parser are copies of `fmt-docx`'s (format crates do not depend on each other).

### Known lossy points

- Masters and layouts of the file are replaced by the built-ins: master graphics, layout-specific
  text styles, footers/date/slide-number placeholders and non-standard layouts are lost; slides are
  mapped to Title / Title and Content / Blank. Placeholder text that relied on the file's master
  styles (size, color, font) is shown with ours (title 44 pt, body 28 pt…) unless the runs set
  them explicitly (LibreOffice always does).
- Shapes that took their look from `p:style` get it resolved into explicit fill/outline/run color;
  effects (shadows, glow) are lost. We never write `p:style`, so text in auto shapes uses the
  master's text color (dark) unless runs set a color – PowerPoint's default white-on-accent comes
  back only when the file stated it.
- Bullet font, color and size (`buFont`, `buClr`, `buSzPct`) and paragraph indents (`marL`,
  `indent`) are not modelled; bulleted paragraphs are written with fixed indents.
- `a:br` is modelled as `"\n"` inside a run (no separate break inline); a vertical tab (U+000B) is
  written as `a:br` and reads back as `"\n"`.
- Compound lines, cropping, transparency, gradients/patterns (first color kept) and preset
  geometries outside the supported library (read as rectangles) are lost. Custom geometry keeps its
  paths but not its guides, handles, connection sites or text rectangle (guides are evaluated once,
  at the shape's size when read).
- Connection sites follow PowerPoint's order for rectangles, flowchart shapes, ellipses and
  triangles; other presets use the four edge midpoints (+ center). A site `idx` past our list
  means the center when rerouting. Rerouting (only when the UI moves glued shapes) uses one turn for
  sites at right angles and two otherwise, never PowerPoint's three/four-turn detours.
- Tables: only "Medium Style 2 – Accent 1" is known for rendering and is spelled out on write;
  other style ids are kept as ids. Cell text direction, diagonal borders, 3-D cells, table
  backgrounds and inline table styles are dropped; row heights are minimums (text may grow rows in
  PowerPoint).
- Font faces map to `a:latin` only; theme east-asian/complex-script slots are written as
  `+mj-lt`/`+mn-lt`.
- Rotations are stored in 1/60000°; a model angle with more precision is rounded on write.
- Transitions: only fade, push, wipe, cover, split, cut and zoom (plus "none" with advance
  settings); PowerPoint 2010+ effects (`p14:*`, `p15:prstTrans`) fall back to the file's
  `mc:Fallback` effect or are dropped; fade through black, sounds and `p:extLst` are lost.
- Animations: only the presets above, whole-shape; Spin is always one clockwise turn and
