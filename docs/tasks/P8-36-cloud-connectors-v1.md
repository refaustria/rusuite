Up to 5 commits. Owner direction (2026-10-16): generic, opt-in, Rusuite offers no cloud service and registers no provider apps.
1. **`FileProvider` interface** (`ui-shared/connectors/provider.ts`): `list(path) → entries (name, kind, size, modified, etag)`, `read(path) → bytes + etag`, `write(path, bytes, { ifMatch }) → etag` (409/412 → `ConflictError`), `mkdir`, `delete`, `rename/move`, `stat`; `Connection { id, kind: "webdav" | (later "s3" | "oauth-generic"), name, baseUrl, auth: { kind: "basic", username, password } | { kind: "bearer", token }, rootPath }`; connections stored on the device only (desktop: Tauri app data dir, encrypted with the OS keyring via `tauri-plugin-stronghold` or `keyring` crate – choose one, document; web: IndexedDB with the password encrypted by a user passphrase? → keep it simpler and honest: web stores credentials in IndexedDB unencrypted but ONLY if the user ticks "Remember password on this device", otherwise asks each session), never synced, never logged; a "Forget all connections" button in the privacy section.
2. **WebDAV transport**: desktop = Rust (`app-common::webdav`, `reqwest` with rustls, PROPFIND depth 1, GET/PUT with `If-Match`, MKCOL, DELETE, MOVE, Basic auth, HTTPS only by default with an explicit "allow http" checkbox for LAN servers; command set `connector_list/read/write/...` exposed by the Tauri shells); web = `fetch` with the same semantics (CORS note: the WebDAV server must allow the site origin – show the exact error and a help link when CORS blocks; Nextcloud/ownCloud need the origin in their CORS config); common `ConnectorClient` in TS choosing the transport via `Backend` (no `window.open`, pointer-event guardrails).
3. **UI**: File › Open and File › Save As gain a left-hand "Connections" section listing configured connections + "Add a connection…"; a file browser pane (breadcrumbs, folder tree, list with name/size/modified, filter by the app's extensions, New folder, Rename, Delete with confirm, Refresh; keyboard navigation; 32 px rows), Save As asks for the file name and warns on overwrite; the Add/Edit connection dialog (name, server URL, username, password, root folder, "Test connection" button with a clear result, "Remember password on this device"); the title bar/status bar shows the connection name for a remote document; Save writes with `If-Match` and on conflict offers "Overwrite / Save a copy / Reload theirs"; recent files remember remote locations (connection id + path) and reopen them; autosave for remote documents stays local (unchanged) with an explicit remote Save; offline/error toasts.
4. **Tests**: unit ≥ 40 (provider contract tests against a fake, WebDAV XML parsing (PROPFIND multistatus, URL escaping, UTF-8 names), conflict handling, dialogs → connection records, recent entries), Rust tests for the WebDAV client against a mock HTTP server (`httpmock` or hand-rolled hyper), e2e 6 against the local Node WebDAV server (add a connection; browse and open an .xlsx from it; Save As a .docx to it and the file exists on the server; conflicting save shows the 3-way choice; forget connections removes stored data (IndexedDB empty); privacy request audit: with no connection configured, still only `/version.json` + self assets; with one configured, requests go only to that host) – keep the existing privacy e2e green.
5. **Web CSP (decision recorded for the owner)**: the live CSP is `connect-src 'self'`; a browser cannot reach a user-configured WebDAV host unless `connect-src` also allows it. Implement the web transport anyway, make the UI detect the CSP block and show "This site's security policy does not allow connections to other servers" with the connection disabled, and prepare (do not apply) the nginx line `connect-src 'self' https:;` + an ADR 0009 amendment text describing the trade-off (documents still never go anywhere the user did not configure; the request-audit e2e proves no background traffic). Desktop needs no CSP change.
