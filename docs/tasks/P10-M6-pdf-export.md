## Decision (do not re-open)
The print pages are HTML. The highest-fidelity PDF with real text comes from the **webview's own PDF renderer**, not from a Rust PDF writer: Android `WebView.createPrintDocumentAdapter()` → `PrintDocumentAdapter.onLayout/onWrite` into a `ParcelFileDescriptor` (vector PDF, one page per `@page`), iOS `WKWebView.createPDF(configuration:)` (iOS 14+) or `UIPrintPageRenderer` + `viewPrintFormatter()` when pagination of the print root needs it (choose the one that honours `@page size` – test the approach by reasoning and document it; prefer `UIPrintPageRenderer` with the paper size from the first page's `@page` for correct pagination), macOS `WKWebView.createPDF` / `NSPrintOperation` to file, WebKitGTK `PrintOperation` with `print-to-file` + `output-uri`, WebView2 `PrintToPdf`. A Rust PDF writer stays a ROADMAP idea.

## Goal
`File › Export PDF…` works on the mobile shells (today Print and Export PDF are hidden there) and produces a PDF file handed to the system "save to" picker, with Share as a second button; the desktop gets the same command where the platform API exists (otherwise the current print-dialog path stays). `File › Print` on mobile becomes "Print…" that hands the same PDF to the system print service (Android `PrintManager.print` with the adapter – the OS dialog offers printers and "Save as PDF"; iOS `UIPrintInteractionController` with the PDF data) – so both commands come back on mobile.
