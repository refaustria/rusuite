## Goal
Everything after "the app exists in the console" is scripted and repeatable: upload the signed Android bundles to a Play track and the signed IPAs to TestFlight, push listing texts, screenshots and release notes to both stores, attach the build to an App Store version and submit for review – each step a command the PM runs with the credentials in the environment, plus a tag-triggered workflow that builds and uploads. App **creation**, Play App Signing enrolment and the questionnaires (data safety, content rating, age rating, app privacy) are console-only and belong to P10-M9; write their checklists.

## Credentials (environment; names only, never in the repo)
Play: `PLAY_SERVICE_ACCOUNT_JSON` (content or path `PLAY_SERVICE_ACCOUNT_FILE`). ASC: `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_PATH` (as `scripts/signing/asc.mjs`). Package/bundle ids: `dev.rusuite.calc|write|show`.

## Items (one commit each)
1. **`scripts/store/play.mjs`** (Node, no new dependencies: JWT RS256 with `crypto`, OAuth2 token exchange, `fetch` against `androidpublisher/v3`): commands `upload --app calc --aab <file> --track internal|closed|production [--rollout 0.1] [--notes docs/store/release-notes/<lang>.txt]` (edits.insert → bundles.upload (resumable/simple) → tracks.update with releaseNotes per language → edits.commit; `--dry-run` validates without commit), `listing push --app calc` (listings for every language in `docs/store/listing/<lang>.json` → title/shortDescription/fullDescription; images: icon, featureGraphic, phoneScreenshots, sevenInchScreenshots, tenInchScreenshots from `docs/store/screenshots/<app>/<form>/*.png` with `images.deleteall` + `upload`; `--langs en,de` subset), `status --app calc` (tracks, latest versionCodes, review state where exposed), `validate` (service account can `edits.insert` for the three packages → prints which apps the account can see – the M9 checklist uses it).
