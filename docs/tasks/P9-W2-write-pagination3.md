## Items (one commit each, with regression tests; up to 5 commits)
1. **Sections with different text widths.** Each section lays out at its own text width (page size, margins, columns, orientation) in the editor's print layout and in print/PDF, including a section change in the middle of a page (continuous section break: the next section's columns start below the break on the same page like Word); a `sectPr` change re-paginates only from that section on. Pages are centred per sheet size (W-18 keeps working).
2. **Notes.** Footnotes are placed at the bottom of the page that holds their reference in the editor's print layout **and in print/PDF output** (not at the end, never duplicated), with Word's separator line; a footnote that does not fit continues on the next page with the continuation separator, and the **continuation text is editable** (the DOM shows one note split across two page footers; edits flow back to the single note); **endnotes at section end** when `w:endnotePr/w:pos="sectEnd"` (Layout › Footnotes dialog option "End of section" / "End of document"); the Footnote and Endnote dialog's number format/restart per section (`w:numFmt`, `w:numRestart`) applied in layout and saved.
3. **Tables across pages.** Nested tables split across pages like their parent rows; cell borders stay open at the bottom of a split row and at the top of its continuation (Word draws no horizontal border there); "Allow row to break across pages" (`w:cantSplit`) and "Repeat as header row" (`w:tblHeader`) respected for nested tables; a row taller than a page is clipped like Word (first page gets the row start) – document the limit.
4. **Speed and measurement.** Flow/page data building for a 12 000-line document in ≤ 5 ms per run (today ~20 ms): cache per-block measurements keyed by content hash + width, reuse unchanged pages; `scripts/perf.sh` gets a pagination case (200-page document: full pagination time, re-pagination after an edit on page 100) written into `docs/perf.md` by the script (the hand-written section is replaced by the generated numbers – keep the explanatory text in `docs/write-layout.md`).
5. **Tests and docs.** Unit tests ≥ 25 (TS: per-section widths incl. continuous breaks, footnote placement/continuation, endnote positions, nested-table splitting and open borders, cache invalidation; Rust: `pos="sectEnd"`, `numFmt`/`numRestart`, `tblHeader`/`cantSplit` on nested tables roundtrip). e2e ≥ 5 on port 4932: a portrait + landscape document shows two sheet widths and prints two page sizes in the PDF (check the print document's page boxes); a long footnote continues on the next page and typing into the continuation edits the note; endnotes "End of section" places them before the next section; a nested table splits with open borders; perf case runs and reports.
