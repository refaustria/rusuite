Notes beyond docs/functions.md:
- AND/OR: iterate all args; direct scalar args use `to_bool` semantics (text that is not TRUE/FALSE → `#VALUE!`); in ranges, only Numbers and Bools are considered (text and Empty ignored); if no logical value at all → `#VALUE!`; errors propagate. NOT takes one scalar. IFERROR(value, value_if_error) is lazy: evaluates `value_if_error` only if `value` is an error; a range in `value` is implicit-intersected (`ctx.scalar`).
- IS* functions never propagate errors; they take ONE arg and use `ctx.scalar` (a multi-cell range → implicit intersection; if that yields `#VALUE!`, ISERROR-style functions return TRUE/FALSE accordingly – follow Excel: ISBLANK(A1:A3) is intersected). ISBLANK is TRUE only for `Empty` (not for `""`).
- Dates are serial numbers in the 1900 system with the Lotus bug: serial 1 = 1900-01-01, serial 60 = the non-existent 1900-02-29, serial 61 = 1900-03-01; for serials ≥ 61 the civil date is `1899-12-30 + serial` days. Implement `datetime/serial.rs` with `ymd_to_serial(y, m, d) -> Option<f64>` and `serial_to_ymd(f64) -> Option<(i32,u32,u32)>` (truncate toward -∞ to whole days; negative serials → `#NUM!` in callers) and unit tests incl. 1900-02-28→59, 1900-02-29→60, 1900-03-01→61, 2024-01-15→45306, 9999-12-31→2958465.
- DATE(y,m,d): y<1900 → y+1900 (Excel: 0–1899 are offset); month/day overflow and underflow roll over (`DATE(2024,13,1)` = 2025-01-01, `DATE(2024,1,0)` = 2023-12-31); result < 0 → `#NUM!`. YEAR/MONTH/DAY accept a number (serial) or numeric text; text dates like "2024-01-15" are parsed in `to_number`? NO – `VALUE`-style date parsing is a text-batch concern; here, non-numeric text → `#VALUE!`.
- WEEKDAY(serial, [type]) types 1 (Sun=1), 2 (Mon=1), 3 (Mon=0); other types → `#NUM!`. DAYS(end, start) = INT(end) - INT(start) (check the DIFF notes in `datetime.tsv` for the exact Excel expectation).
- TODAY() = floor(ctx.now()), NOW() = ctx.now(); both take no arguments. Tests inject `now` via `EvalContext { now: || 45306.75, .. }`.
