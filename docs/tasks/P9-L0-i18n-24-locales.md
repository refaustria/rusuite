## Items (one commit each; up to 5 commits)
1. **Locale registry.** `LOCALES` with the 24 languages: `bg` Български, `cs` Čeština, `da` Dansk, `de` Deutsch, `el` Ελληνικά, `en` English, `es` Español, `et` Eesti, `fi` Suomi, `fr` Français, `ga` Gaeilge, `hr` Hrvatski, `hu` Magyar, `it` Italiano, `lt` Lietuvių, `lv` Latviešu, `mt` Malti, `nl` Nederlands, `pl` Polski, `pt` Português, `ro` Română, `sk` Slovenčina, `sl` Slovenščina, `sv` Svenska (native names, English names, BCP-47 tags for `Intl`, `<html lang>`); `navigator.language` best match (`pt-BR`→`pt`, `de-AT`→`de`, `en-*`→`en`, unknown → `en`); a locale whose catalog is missing falls back to English with a console note (so the apps work while translations land one by one). Catalog loading becomes **lazy per language** (dynamic import of `locales/<lang>.json` for ui-shared + the app; English bundled) so 24 catalogs do not bloat the initial bundle; the switch awaits the load, then re-renders.
2. **Plurals and formats.** `t()` selects the plural category with `Intl.PluralRules` (`zero/one/two/few/many/other` keys; English/German keep `one/other`); `formatNumber`/`formatDate`/`intlLocale` per locale; `formatCombo` key names per language (Ctrl/Strg/…: keep a table of the localized modifier and key names Office uses – e.g. German Strg/Entf/Umschalt, French Ctrl/Suppr/Maj, Spanish Ctrl/Supr/Mayús; default to the English names where Office keeps them); list/number/date pickers in the apps use the locale (UI chrome only – cell values stay en-US per the owner's decision).
3. **Checks.** `scripts/i18n-check.mjs` generic over every `*.json` in each locales dir: parity with `en.json` (keys and placeholders), plural completeness per language (`Intl.PluralRules(lang).resolvedOptions().pluralCategories`), **informal-register check per language** (a per-language list of formal pronouns/verb forms, e.g. de `Sie|Ihnen|Ihr…` (existing), fr `\bvous\b|\bvotre\b|\bvos\b`, es `\busted(es)?\b|\bsu(s)?\b` (careful – allow-list needed), it `\bLei\b|\bSuo\b`, nl `\bu\b|\buw\b`, pl `\bPan\b|\bPani\b|\bPaństw`, hu `\bÖn\b`, ro `dumneavoastră`, cs/sk `\bVy\b|\bVás\b|\bVám\b`, pt `\bvocê\b`? (pt-PT informal is "tu" – decide and document), sv/da `\bNi\b`, fi `\bTe\b|\bTeidän\b`, el `σας` (formal plural – allow-list), bg `Вие`, hr/sl `\bVi\b|\bVam\b|\bVas\b`, lt `\bJūs\b`, lv `\bJūs\b`, et `\bTeie\b`, ga/mt: document the convention) with an allow-list file per language and a stale-entry report like the German one; the check also flags untranslated values (identical to English for non-English catalogs, except an allow-list of brand names/symbols) once a catalog exists. `pnpm i18n:check` keeps passing with only EN/DE present.
4. **UI and portal.** Language picker (View › Language group, backstage, Options) shows native names in a searchable list grouped A–Z, current language first; the portal's EN/DE switch becomes a dropdown over `LOCALES` with per-language `data-i18n` catalogs (`apps/portal/locales/<lang>.json`, lazy), remembering the choice as today; desktop file dialogs take the filter names from the catalog of the current language; `<html lang>` and `dir="ltr"` set (no RTL language in the set).
5. **Tests and docs.** Unit tests ≥ 25 (registry/matching, lazy loading + fallback, plural categories for pl/cs/lt/ga/mt/ro/sl, formatCombo tables, i18n-check rules incl. the register check with fixtures); a generated **render test per language** in each app (`i18n.test.ts` iterates `LOCALES` and renders the ribbon + backstage with that language, skipping languages whose catalog is missing with a visible "pending" count); e2e: language switch to a locale without catalog falls back cleanly; portal dropdown lists 24 entries; German still informal. `docs/i18n.md` rewritten for 24 languages (how to add a language, the register rule, glossary workflow); `docs/i18n-glossary/README.md` template: ribbon tabs, groups, common commands, dialog buttons, file types – columns English / Office term in the language / note.
