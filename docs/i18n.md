Danish `da`, German `de`, Greek `el`, English `en`, Spanish `es`, Estonian `et`, Finnish `fi`, French `fr`, Irish `ga`,

Portuguese `pt` (European, `pt-PT`), Romanian `ro`, Slovak `sk`, Slovenian `sl`, Swedish `sv`. **English, German, French, Spanish,

English (with "(not translated yet)" next to its name). Every user-visible string lives in a catalog.

## Choosing the language

- Default: the best match of the browser/webview languages (`navigator.languages`, most preferred first): the first one
  whose primary subtag is a UI language (`de-AT` → German, `pt-BR` → Portuguese, `en-GB` → English); none → English.
- The user's choice overrides it: **View › Language / Sprache** (a ribbon group in every app), the picker at the bottom of
  the **File** backstage, **File › Options… › Language** (a searchable list: own name, English name or code) and the
  language list at the top right of the portal. All pickers show the languages by their own names, the current one
  first, then A–Z (Greek and Cyrillic names after Latin). The choice is stored in `localStorage` under `rusuite.locale`.
  On the web the portal and the apps share one origin, so a choice made on the portal opens the apps in that language and
  vice versa; in the desktop shells the key lives in the webview's storage in the app data directory.
- Switching loads the language's catalogs if needed, then re-renders the open window in place (no reload, the document
  and its undo history stay) and sets `<html lang>` (and `dir="ltr"`: no right-to-left language in the set).
- A language without catalogs yet shows English: the choice is stored all the same (it applies once the catalogs exist)
  and the console notes `rusuite: no <English name> (<code>) translation yet – showing English` once (see "Fallback tests").

## Library (`packages/ui-shared/src/i18n/`, no runtime dependency)

| Export | |
| --- | --- |
| `LOCALES`, `localeInfo(id)`, `isLocale`, `type Locale` | the registry (`locales.ts`): `{ id, label (own name), english, tag (BCP 47 for Intl) }` |
| `matchLocale(langs)` (`localeFromLanguage`) | best UI language for a browser language or a preference list |
| `pickerGroups(current, query?)` | the picker order: current first, then groups by first letter; `query` filters |
| `createI18n({ locales, fallback })` | an `I18n` with `translate(locale, key, params?)`, `bind(locale)`, `has`, `extend` |
| `t(key, params?)` | translates in the current language (outside React, or in a component that called `useT`) |
| `useT()` | `t` bound to the current language; the component re-renders when it changes |
| `useLocale()`, `getLocale()`, `subscribeLocale` | the language shown |
| `setLocale(l, { persist })` / `switchLocale(l, { persist })` | switch (fire-and-forget / a promise that resolves once the language is shown) |
| `loadLocale(l)`, `hasCatalog(l)`, `availableLocales()` | lazy catalogs: load one language, ask whether it has catalogs |
| `addCatalogs(bundled, lazy)`, `catalogLoaders(glob)` | registers a package's catalogs (`apps/*/src/i18n.ts`); `addMessages(bundled)` still works |
| `<I18nProvider locale?>` | app root (`main.tsx`); with `locale` it forces a language without persisting it (tests); renders nothing while the first language loads |
| `withLabel(base, key, params?)` | a constant option (paper size, number format, layout …) whose `label` is translated when read |
| `LanguageSelect`, `LanguageList`, `languageRibbonGroup(t)` | the pickers (select for ribbon/backstage, searchable list for Options) |
| `pluralForm(n, l)`, `pluralCategories(l)` | `Intl.PluralRules` of the language |
| `formatNumber`, `formatDate`, `intlLocale` | `Intl` formatting of the UI chrome (status bars, recent list, presenter clock) in the language's tag (`fr-FR`) |
| `formatCombo(spec)`, `KEY_NAMES` (`keyNames.ts`) | shortcut texts with the key names of that language's Office |

Messages are flat, namespaced keys (`ribbon.file`, `backstage.saveAs`, `calc.fmt.title`, `show.order.bringToFront`) with
`{name}` placeholders. Missing keys fall back to English, then to the key itself.

**Plurals** use the CLDR categories of the language (`Intl.PluralRules`): a plural message is a group `key.one` +
`key.other` in English, and in each language one key per category that language has – `zero`, `one`, `two`, `few`,
`many`, `other`. `t("print.range.pages", { count })` picks `key.<category>`, else `key.other`. English and German have
`one/other`; Polish, Czech, Slovak and Lithuanian `one/few/many/other`; Irish and Maltese `one/two/few/many/other`;
Slovenian `one/two/few/other`; Croatian and Romanian `one/few/other`; Latvian `zero/one/other`; French, Spanish, Italian
and Portuguese `one/many/other` (`many` is used for millions: "1 000 000 de fichiers"). `pnpm i18n:check` lists what a
language needs. A lone `key.other` without `key.one` in English is an ordinary key ("Other error").

**Shortcut key names**: keep shortcuts as combo specs (`Mod+Shift+S`) and show them with `formatCombo`. The key names
come from `KEY_NAMES` in `keyNames.ts`, as that language's Office prints them: German `Strg+Umschalt+S`, `Entf`,
`Eingabe`, `Pos1`; French `Ctrl+Maj+S`, `Suppr`, `Entrée`, `Échap`; Spanish `Ctrl+Mayús`, `Supr`; Italian `Maiusc`,
`Canc`, `Invio`; Swedish/Danish `Skift`, Finnish `Vaihto`. A language or key not in the table keeps the English name
(`Ctrl`, `Shift`, `Alt`, `Delete` – most Office localisations do); macOS shows `⌘` and `⌥`.

**Lazy catalogs**: English and German are bundled. Every other `locales/<lang>.json` is found by Vite's
`import.meta.glob` in `packages/ui-shared/src/i18n/locale.ts` and `apps/*/src/i18n.ts` and becomes a chunk of its own
(about 35 KB shared + 50–90 KB per app and language, uncompressed), fetched once when the language is chosen or detected.
At start-up in such a language `<I18nProvider>` waits for it, so the UI does not flash in English.

Catalogs: `packages/ui-shared/src/i18n/locales/<lang>.json` (ribbon chrome, backstage, dialogs, print panel, formatting
controls, shared commands `cmd.*`, tab and group names `tab.*` / `group.*`), `apps/{calc,write,show}/src/locales/<lang>.json`
(prefix `calc.` / `write.` / `show.`), `apps/portal/locales/<lang>.json` (prefix `portal.`, fetched by `apps/portal/i18n.js`).
Components import `t`/`useT` from their app's `src/i18n.ts`, which registers the app catalog first.

Rules for new UI text:

1. Never write UI text as a literal: add the key to `en.json` **and** `de.json` and use `t("…")`. Feature work adds
   keys to English and German only; the other catalogs get them later (see "Pending keys" below).
2. A component that renders translated text calls `useT()` (memoised maps such as the shortcut map list `t` in their
   dependencies), so a language switch re-renders it.
3. Shortcuts: combo specs and `formatCombo`, never a written-out key name.

## Adding a language (P9-L1 … L11)

A translation task adds exactly these files for language `<lang>` (all at once – the check fails on a language present in
only some places):

1. `docs/i18n-glossary/<lang>.md` – first: the Office terms of the language (template in `docs/i18n-glossary/README.md`).
2. `packages/ui-shared/src/i18n/locales/<lang>.json`
3. `apps/calc/src/locales/<lang>.json`
4. `apps/write/src/locales/<lang>.json`
5. `apps/show/src/locales/<lang>.json`
6. `apps/portal/locales/<lang>.json`, plus `"<lang>"` in `CATALOGS` in `apps/portal/i18n.js` (one line; the check compares it with the files)
7. optional: `scripts/i18n-allow/<lang>.json` (allow-list, see Checks) and the language's key names in `KEY_NAMES`
   (`packages/ui-shared/src/i18n/keyNames.ts`) if its Office does not use the English ones.

Nothing else: the registry already lists the language, the pickers drop "(not translated yet)", the catalogs are picked
up by the glob, and the per-language render tests of the three apps (`apps/*/src/i18n.test.tsx`) start running for it.
Each catalog has every key of `en.json` with the same `{placeholders}`, one key per plural category of the language,
values in the informal register and in Office terminology. `pnpm i18n:check` and `pnpm test` must pass.

## Pending keys (P9-L0b)

English and German are the **core** catalogs and must always be complete. Feature tasks add new keys to `en.json` and
`de.json` only, never to the other languages. In a translated language a key that is in `en.json` but missing from its
catalog (an ordinary key, or a whole plural group) is **pending**: the runtime shows the English text, and
`pnpm i18n:check` prints `<lang>: N keys pending (<catalog file> n, …)` per language and does not fail. Everything else
still fails in every language: an extra key, a placeholder mismatch, a plural group with only some of the language's
categories, an untranslated value, a formal form.

Translated languages catch up in their review tasks (P9-LR*), which add the pending keys, and at the **completeness
gate**: `pnpm i18n:check:strict` (`--strict`, or `I18N_STRICT=1`) makes every pending key a finding. The PM runs it at the
end of a translation block, and the release checklist runs it before tagging (docs/release.md).

## Checks

- `pnpm i18n:check` (`scripts/i18n-check.mjs`, run in CI), for every `<lang>.json` in every locales dir:
  - parity with `en.json`: the same keys (a key missing outside en/de is pending, see above; `--strict` fails it), the
    same placeholders; plural groups need exactly the categories of the
    language (`Intl.PluralRules(lang).resolvedOptions().pluralCategories`), each variant using only the placeholders of
    the English group; a file name that is not one of the 24 codes, or a language missing in some dirs, fails;
  - the **informal register** per language (`REGISTER` in the script; see Tone below);
  - **untranslated values**: a value identical to English with two or more words fails, unless it consists of brand and
    technical names only (`BRANDS`: Rusuite, Excel, Unicode, UTF, PDF, Windows …) or the allow-list names it (single
    words such as "Layout" or "Status" are often the same and are not flagged, units such as "(cm)" do not count as a
    word). An agent adding a German (or other) value that is legitimately the same as English with two or more words adds
    `"<locales dir>:<key>": "<reason>"` under `untranslated` in `scripts/i18n-allow/<lang>.json`;
  - and, as before: no literal JSX text, `aria-label`, `title`, `placeholder`, `alt` or label props (`label`, `tooltip`,
    `confirmLabel`, …, `label:` in objects, sentence-like literals in conditions) in `packages/ui-shared/src` and
    `apps/{calc,write,show}/src`; every literal `t("key")` exists; every `data-i18n*` key of the portal exists; the
    portal's `CATALOGS` match its catalog files. Allowed literals: brand names, file extensions, `fx`, shortcut combos,
    symbols; a line can opt out with `// i18n-ignore: <reason>`.
- **Allow-lists** per language: `scripts/i18n-allow/<lang>.json` –
  `{ "register": { "<locales dir>:<key>": "reason" }, "untranslated": { "<locales dir>:<key>": "reason" } }`, e.g.
  `"apps/calc/src/locales:calc.filter.top10Title": "German Excel also says Top 10 AutoFilter"`. Entries that no longer
  match are reported as stale. Prefer rewording over an entry.
- Tests: `packages/ui-shared/src/i18n/i18n.test.tsx` (interpolation, plurals, fallback, persistence, `<html lang>`,
  re-rendering), `locales.test.tsx` (registry, matching, plural categories, lazy loading and fallback, key names,
  pickers), `check.test.mjs` (the rules of the check with fixtures, and the check on the repository); each app's
  `src/i18n.test.tsx` renders the app in **every language with catalogs** (ribbon, backstage, `<html lang>`, no raw
  keys – `packages/ui-shared/src/i18n/renderSuite.ts`) and skips the others, counted in a test titled
  `pending: N of 24 languages without catalogs yet (…)`.
- e2e (`packages/e2e/tests/i18n.spec.ts`): a German browser gets "Start" and "Speichern" in all three apps, informal;
  for every language in `TRANSLATED` (de, fr, es, it, pt, nl, sv, da, fi, pl, cs, sk, sl, hr, hu, ro, bg, el, lt, lv, et, ga, mt – a translation task adds its language there) each app is
  switched via View › Language and the portal via its language list, and the spec checks, with the values of the
  catalogs (`packages/e2e/support/i18n.ts`): the Home and View tabs, the status bar's "Saved", the backstage's Save /
  Save As buttons and privacy text, no formal form (the `REGISTER` rule of the check) in the backstage and on the
  portal, and **no clipped ribbon label** on any ribbon tab at 1400 px and 1024 px (a text element that clips –
  overflow, ellipsis, line clamp – while its text is larger than its box, or a group bar that still overflows).
  A browser in each translated language (`BROWSER_TAG`: `nl-NL`, `fi-FI`, `pl-PL`, `sl-SI`, `ga-IE`, `mt-MT` …) gets that language in all three apps
  (Home tab, Save As and "Recent" in the backstage, informal), and the portal's choice carries over to Calc (P9-LR2;
  this replaced the per-language specs `i18n-l3/l4.spec.ts`). View › Language survives a reload; Options › Language searches and switches; a browser whose language is declared catalog-less (`mt`, see "Fallback tests")
  gets English without errors and the picker lists 24 languages; the
  portal's language list (24 entries) persists and carries over to Calc. `I18N_SHOTS=<dir>` saves screenshots (each
  language's Home tab and backstage, every ribbon tab at 1024 px).

## Fallback tests (P9-L11)

The behaviour for a registered language without catalogs ("(not translated yet)" in the pickers, English on screen, the
console note, the stored choice) needs a test language, but every language gets its catalogs eventually. The tests
therefore **declare** a language catalog-less instead of relying on a missing file: the test-only hook
`globalThis.__rusuiteNoCatalog = ["mt"]` (an array of registered language ids) makes `hasCatalog()` in
`packages/ui-shared/src/i18n/locale.ts` – and `hasCatalog` in `apps/portal/i18n.js` – answer `false` for those ids, so
`availableLocales()`, the picker labels, the start-up language and `switchLocale` behave as for a language without
files. Nothing in the product sets it.

- Unit tests (`locales.test.tsx`): a `beforeEach` sets the hook to `["mt"]`, `afterEach` deletes it; one assertion checks
  that without the hook Maltese has its catalogs.
- e2e (`i18n.spec.ts`, "Languages without catalogs yet"): a Maltese browser (`mt-MT`) with
  `page.addInitScript(() => { window.__rusuiteNoCatalog = ["mt"] })` gets English in the three apps and the portal, the
  pickers list `Malti (not translated yet)` and choosing it keeps English; the same language is tested as a translated one
  in the `TRANSLATED` loop (no hook).
- The per-language render tests of the apps (`renderSuite.ts`) never set the hook, so they run for every language with
  files; the `pending: N of 24 languages without catalogs yet` count only lists languages without files.

## Review checklist (P9-LR*)

A review task is the second pair of eyes on two to four translated languages. Per language:

1. **Pending keys first**: `pnpm i18n:check` lists them; translate them (same rules, key order = `en.json`) until
   `pnpm i18n:check:strict` passes for the language.
2. **Sample**: every 20th key of each of the five catalogs (> 250 strings) plus *all* keys of the areas translators
   find hard: `tab.*`, `group.*`, `cmd.*`, `show.fx.*` / `show.trans.*` (the localised PowerPoint effect and transition
   names), `show.setup.*`, `show.media.*`, `calc.pivot.showAs.*`, `write.listPreset.*`, `reader.*`, `ai.*`.
3. **Check each string** for: meaning; Office terminology (the glossary; the real localised Office name for
   commands, tabs, dialogs, effects); register – informal everywhere, including hidden formal forms the check cannot
   see (verb forms: French "-ez" / "veuillez", Spanish "haga/seleccione", Italian "selezioni/inserisca", Portuguese
   "clique/selecione/introduza"; a third-person possessive that reads as address – Spanish "su", Portuguese "seu/sua":
   name the owner instead, "la carpeta de datos de la aplicación"); grammar and agreement; placeholders; length
   (ribbon labels ≤ German + 15 %); orthography of the variant (pt-PT after the 1990 agreement: "para", not "pára").
4. **Hunts over the whole language** (scripts, not samples): the formal verb forms above as regexes; sentence-initial
   words (they show the imperative forms in use); one English term → several translations across the five files
   (keep one unless grammar or the Office context differs); formula-language names (TRUE/FALSE, function names stay
   English, see below – mention the localised name only next to the English one).
5. **Plurals**: `.many` (millions in fr/es/it/pt) needs its own form where the language does ("{count} de pages").
6. **Glossary**: complete `docs/i18n-glossary/<lang>.md` with the terms actually used; correct the catalog where they
   disagree; set the reviewer line.
7. **e2e**: the language is in `TRANSLATED` of `i18n.spec.ts`; run the spec on the task's port and fix strings (never
   the UI) until no ribbon label is clipped.
8. **Hunts added by P9-LR2** (also scripts): control characters in values (a JSON `"\n"` where English has the
   literal switch `"\\n"` – Word field switches such as `(\n)` became line breaks in da/fi); punctuation and symbol
   parity with English (`…`, `›`, `(`, `\`, `%`); values much shorter than English (dropped sentences); the language
   picker label `language.label` = "<word for *language*> / Language", not the language's own name; the
   **slide/section vocabulary of the PowerPoint localisation** across all of Show (Danish PowerPoint says "dias" and
   "sektion", not "slide" and "afsnit" – "afsnit" is the paragraph); prefixes left as a whole value (Finnish "Kaksois"
   for *Double*); the language's own quotation marks (Finnish/Swedish ”…”); the plural `.one` reading naturally for 1
   ("Select All {count} Instance" → "{count} … selecteren"). Keys ending in `.zero`/`.two` without an English plural
   group (`calc.chart.blanks.zero`, `write.columns.two`) are ordinary keys, not plural forms.
9. **Hunts added by P9-LR3** (Slavic languages; scripts over all values): gendered forms addressed to the user hide in
   more than the past tense – conditionals ("Jak opisałbyś…"), predicative adjectives ("Ak si chceš byť istý",
   "připraven", "prepričan"): use an infinitive or reword ("Jak opisać…", "Ak si chceš overiť"); the grammatical gender
   of the PowerPoint word for *slide* everywhere in Show (Slovak *snímka* is feminine: "žiadna snímka", Czech *snímek*
   masculine); which CLDR category holds the fractions (cs/sk `.many`, pl `.other`: genitive singular, and a
   participle in front agrees with the numeral – sk "Nahradené 1,5 bunky", not "Nahradenej"); the `.one` of
   "all N" messages without "all"; unit presets that show inches in English (`(1 in)`) take the German cm values;
   one name for two different effects in a gallery (Slovenian Spin and Swivel were both "Vrtenje"); brand names
   declined where the language declines them (Slovak "na GitHube"); a word for *spacing* that means *line spacing*.
10. **Hunts added by P9-LR4** (scripts over all values): a control character at the end of a value where English has
   none (the last key of every catalog file ended in `"\n"` in hr/hu – a trailing line break the check does not see);
   in languages whose CLDR `one` also covers 21, 31, 101 … (Croatian, like the other South Slavic ones) the `.one` text
   keeps `{count}` and never reads as a bare singular ("Oporavljeni dokument" → "{count} oporavljeni dokument");
   gendered forms addressed to the user in conditionals and predicative adjectives also outside the Slavic languages
   (Croatian "Kako bi opisao", "Da bi bio siguran", Bulgarian "Как би описал", Romanian "Ca să fii sigur"): reword
   impersonally ("Kako opisati…", "Как би се описала…", "Ca să verifici…"); the grammatical gender of nouns inside
   gallery names (Bulgarian *диагонал* is masculine: "Светъл низходящ диагонал"); Office near-synonyms with a different
   meaning (Romanian "Organigramă" is the org chart, flowchart shapes are "Schemă logică"; Croatian "Izlet" for *Fly
   Out* means an excursion); one word for two different things in one place (Bulgarian *Emphasis* animations and the
   *Underline* effect were both "Подчертаване"; Romanian *Fall Over* and *Flip* both "Răsturnare"); an index-slip scan:
   a value that is the catalog's usual translation of a neighbouring key's English (none found in hr/hu/ro/bg).
11. **Report** per language: strings reviewed, changes per category (meaning, terminology, register, grammar, length,
   consistency, plurals, pending), remaining doubts by key.

## Not translated (on purpose, for now)

- **Formula language**: function names stay English (`SUM`, not `SUMME`), the argument separator stays `,` and the decimal
  point `.`, error values stay `#REF!` etc. Calc's formula diagnostics (`apps/calc/src/formula/`) and the cores' error
  and info messages (Rust: parse errors, "Replaced 3 occurrences", cycle notes) stay English. Only the
  wrapper around a formula error ("… – fix or press Esc to discard") is translated. Reader warnings are translated by
  their codes (see "Reader warnings" below); the parts they quote from the file or from another component (element
  names, `{error}` texts of the model) stay as they are.
- **Cell values**: number and date display in cells stays en-US (Format Cells previews included).
- **Document content**: placeholder prompts on slides and default names are UI (translated); text that ends up in a saved
  file (style ids, a pasted picture's name) is not.

A follow-up task may add locale-aware input/display and `;` separators if the owner wants it (see STATUS).

## Reader warnings (W-26: fmt-docx; fmt-xlsx and fmt-pptx since P9-X2)

The file readers report what they dropped or approximated as **coded warnings**: `{ code, params, text, count }`
(`ReaderWarning` of `fmt-docx`, `fmt-xlsx` and `fmt-pptx`, sent by write-, calc- and show-core in the `opened` /
`peeked` replies, TypeScript in `apps/*/src/generated/ReaderWarning.ts`). `code` is stable (`docx.run.propertyDropped`,
`xlsx.cell.isoDate`, `pptx.line.dash`), `params` fills the `{name}` placeholders, `text` is the English line (the
fallback), `count` how often it occurred (repeats are merged). The shared catalog holds every message under
`reader.<code>` (`packages/ui-shared/src/i18n/locales/<lang>.json`); `readerWarningText(w)` (`@rusuite/ui-shared`)
translates it in the UI language, adds "(N×)" for repeats and falls back to `text` for an unknown code or a plain
string. The status bars of Write, Calc and Show show the warnings with it (the tooltip lists all of them).

- **One template per code.** fmt-xlsx and fmt-pptx keep their codes with the English templates in one table
  (`TEMPLATES` in `crates/fmt-{xlsx,pptx}/src/warn.rs`); a call site names the code and its parameters
  (`note!("xlsx.cell.isoDate", cell = at)`), and a context the caller knows is added as a parameter
  (`.with("sheet", name)`: the template of every note read inside a sheet starts with `sheet "{sheet}": `). fmt-docx
  writes the template at the call site (`w.warn(code, template, params)`).
- **Tests**: each reader's unit test compares its codes with `en.json` (same text) and `de.json` (a message with the
  same placeholders), and checks that every code in the sources has a template (fmt-docx
  `warning_sites_are_consistent`, fmt-xlsx / fmt-pptx `templates_match_the_ui_catalogs`); a debug assertion fails a
  note whose parameters do not match its template. `readerWarning.test.ts` checks the German placeholders of every
  `reader.*` key. Notes `fmt-ooxml` produces for charts (English strings) are mapped to `xlsx.chart.*` /
  `pptx.chart.*` codes; an unknown one becomes `*.chart.other` with the English `{text}`.
- **New warnings** add the code to the reader's table and `reader.<code>` to `en.json` and `de.json` (the other
  languages get it as a pending key, see above). `ReadOutput::warnings` keeps the English lines for tools and tests
  (fmt-xlsx: one line per occurrence, as before); `ReadOutput::details` has the coded warnings.

## Desktop file dialogs

The shells' `open_file_dialog` / `save_file` commands take an optional `dialog: { title, filterName }` from the UI
(`TauriBackend` passes the translated "Open" / "Save As" and the app's file type from the catalog of the current language,
`calc.fileType` / `write.fileType` / `show.fileType`, e.g. "Excel-Arbeitsmappe"); without it the dialog keeps the
platform title and the English filter name. A new language therefore only needs those keys in its catalogs. (Calc's
"CSV / TXT" filter label is the same in every language.)

### German

German addresses the user informally: **du / dich / dir / dein**, imperatives without "Sie" ("Wähle…", "Öffne…"). Never "Sie / Ihnen / Ihr(e)" as a form of address. `pnpm i18n:check` fails on formal forms in `de.json` values (P8-48): a capitalised `Sie`, `Ihnen`, `Ihr`, `Ihre`,
`Ihrem`, `Ihren`, `Ihrer` or `Ihres` anywhere in a value (`\b(Sie|Ihnen|Ihre?[mnrs]?)\b`, case-sensitive, so the
lower-case third-person "sie/ihr/ihre" is fine). For a genuine third-person use at the start of a sentence ("Sie werden
geleert" = "they are cleared") first try rewording ("Die Zellen werden geleert", lower case after a colon); if that is
not possible, add `"<locales dir>:<key>": "<reason>"` to `register` in `scripts/i18n-allow/de.json` (or, as before, `FORMAL_ALLOW` in `scripts/i18n-check.mjs`) (for example
`"apps/calc/src/locales:calc.pivot.deleteConfirm.one": "Ihre = its cells"`). Entries whose value no longer matches are
reported as stale. The e2e German tests also assert that the backstage of each app and the portal show no formal form.
